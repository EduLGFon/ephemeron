# Decisions

Decisions not covered by PLAN.md (lighter-weight option chosen by default).

- Cancelled exception rows act as EXDATE equivalents; no separate EXDATE column.
- Root .gitignore bare `test` rule ignores new test files; force-add them.
- image 4.3.0 has no WebP encoder; attachment compression re-encodes to JPG q80 (opaque) or resized PNG (alpha) at max 1600 px; files under 200 KB skip re-encoding. No WebP, no version upgrade.
- Native alarm classes lived in com.example.ephemeron while app namespace is com.spotnik.ephemeron, so receivers never fired and MainActivity could not resolve AlarmPlugin; moved to com.spotnik.ephemeron.
- Alarm snooze keeps gentle default preset (per-alarm preset not persisted in alarms_index).
- Snoozed alarms use state `snoozed` (Dart and native snooze paths, written after schedule upsert); every pending-alarm query includes `scheduled` and `snoozed`; window rebuilds preserve snoozed rows and request codes until fire or resolve.
- Meet join uses tiny ephemeron/system channel (ACTION_VIEW) instead of url_launcher; unsupported platforms fall back to copy-link.
- Dropped without devices/SDK (owner instruction 2026-10-30): physical-device alarm matrix, 60 fps bench, 24 h battery bench, APK/AAB size audit, 3-day real-account soak, MediaPlayer-on-alarm-stream sound, flashlight blink.
- Widget tests: close in-memory Drift DB and unmount inside test body before final pump; otherwise Drift stream-close zero-timer trips pending-timer check (addTearDown close runs too late).
- Session restore (PLAN 8.1/8.2): lightweight UI state (tab, route, calendar anchor/view/dayCount, selected list/folder, search query/scope, focus options, open-sheet marker) in SharedPreferences for sync read at startup; form contents in existing Drift drafts table, autosaved debounced 500 ms. No new dependency. Markers set when sheet opens and cleared in dispose (process kill skips), so kills restore but normal closes do not; drafts expire after 7 days, reopen silently under 24 h and behind "Restore draft?" banner above that. Notes need no draft row (autosave to DB).
- Google sync account linking (2026-11-03, Android tasks never synced): Calendar-only sign-in on Android meant Tasks calls 403d and engine deleted outbox rows as stale, then 401d on everything after expiry, while chip read synced. Fix: sign-in requests Calendar + Tasks everywhere (desktop already did); 401/permission-403 keeps row with backoff and raises reconnect banner instead of deleting; events and tasks gain googleAccount (schema v9, backfilled from parent calendar/list) so push/pull/discovery scoped per account and one account's loop can no longer 404-drop another's rows.
- Full-screen alarms keep existing Flutter RingScreen (no native alarm UI). Dedicated native activity may replace later.
- Biometric exemption: ring screen shown without _LockGate only when activeRingRequestProvider set from verified alarms_index row in state `fired`. Native intents alone never bypass gate; unknown/scheduled/missed/dismissed row rejected silently.
- Alarm fire marks row `fired` (or `missed` when notifications off) before posting, so full-screen tap always reads settled state. Notifications use setOnlyAlertOnce so foreground-service updates and minute repeats cannot re-alert or flash.
- full_long minute repeats restart AlarmRingService without posting new notification; only first fire notifies. phase extra carried through service re-posts so focus next-phase actions survive.
- Occurrence cache source labels (schema v14): occurrence_cache.source_label and source_account filled at rebuild time from event calendar or task list using shared source-label helpers. Rows created before upgrade keep null labels until next rebuild; timeline/agenda/month surfaces hide empty labels and never query per row.
- Shared calendar claims: one owner/reader election per shared calendar. When signed-in account list unknown (null), shared pull fails closed instead of pulling once per account. Stale cal:reader:<remoteId> keys removed only when provably stale (owner signed in, calendar gone or disabled, or no live reader); legacy cal:<id>:token rows deleted once cal:v2:<id>:token key exists.
- Sync diagnostics: Sync issues screen renders only allowlisted operation/entity/error labels plus attempt counts and ages. Outbox payloads, syncState values/tokens, account emails, titles, raw response bodies never passed to widgets. Discard offered only after retries exhausted; read-only SourceMoveException discards pending operation instead of retrying forever.
- Microsoft remote deletions: calendars absent from complete /me/calendars soft-deleted only when owned by account, clean, remote-backed. Events reconciled only inside completely fetched calendarView window and only when clean, non-recurring, provable overlap. Tombstones revive when remote row reappears. Graph paginator throws instead of returning partial listing at page cap, so partial listing can never trigger deletion.
- Read-only calendars: source read-only enforced at repository boundary for create/move/edit/delete/attendee/RSVP, mirrored in details/timeline/editor UI. Moving exception resolves to master so series never leaves orphan exception in another calendar.
- Single-occurrence integrity: exception uses own reminders and alarm preset when set, otherwise inherits master's. Details edit/delete target exact occurrence; new exception inherits master location/Meet/visibility/transparency/reminders/preset/color when not overridden.
- Calendar quick create: all-day strip always rendered with 32dp minimum empty-day target; month cells create 09:00 timed event on long-press. Explicit all-day or time intent from gesture wins over autosaved draft.
- Device calendars stay user-initiated import/refresh with fixed [now-30d, now+365d] window; no background live sync (battery/API cost). Mappings pruned only for visible calendars deselected in completed import, keeping invisible and other-target mappings.
- Localization: UI remains English-only by decision. intl used for formatting and only existing ARB keys localized. Full localization pass is separate owner-approved effort.
- Startup state: calendar rebuild fallback and session restore coalesce into one scheduled build; matrix board waits for saved mode (Auto only after real load error); task-chip tooltip uses manual trigger mode so touch long-press reaches management while desktop hover still works.
- File-size review: after two split passes, modules slightly above 300 lines (300-400 range, e.g. device_calendar_import_service.dart, calendar_settings_screen.dart, sync_engine.dart, focus_screen_start.dart) are cohesive single-responsibility and kept rather than split mechanically. app_localizations.dart follows ARB source. Earlier outliers (570, 568, 456, 435, 427, 422, 414, 413, 412) now split into part files under 300 lines.
